# ScriptAgent 需求文档

## 1. 文档目的

本文档用于确认 ScriptAgent 第一版产品需求，并作为后续开发过程中的持续维护依据。

开发过程中，凡涉及功能范围、用户流程、接口、数据结构、模型行为、CreatiBI 写入方式、前端页面结构或验收标准的变更，都必须同步更新本文档。

## 2. 产品概述

ScriptAgent 是一个面向 CreatiBI 脚本生产流程的内部工作台。用户上传参考视频和产品信息 Markdown 文件后，系统调用 `qwen3.6-plus` 完成视频理解，并生成复刻脚本和多个裂变脚本。用户可在前端查看历史记录、检查生成结果，并手动确认是否发布至 CreatiBI。

## 3. 目标用户

- 创意脚本策划人员。
- 广告素材生产人员。
- 需要基于参考视频快速生成复刻和裂变脚本的运营人员。
- 使用 CreatiBI 管理脚本和创意素材的内部团队。

## 4. 核心目标

- 降低参考视频拆解成本。
- 将视频分析结果稳定输出为详细 Markdown 分镜表。
- 基于产品 Markdown 生成可用的复刻脚本。
- 基于同一结构生成多条裂变脚本。
- 保存每次生成任务，方便回看和复用。
- 程序关闭后再次启动，历史任务和上传文件仍然保留。
- 在用户确认后将脚本写入 CreatiBI。

## 5. 第一版范围

第一版必须包含：

- 前端工作台页面。
- 参考视频上传。
- 产品 Markdown 上传。
- 用户补充要求输入。
- 裂变数量设置。
- 历史记录列表。
- 任务详情查看。
- 任务运行日志查看。
- 任务重试。
- 视频理解 Markdown 输出。
- 复刻脚本 JSON 输出。
- 裂变脚本 JSON 输出。
- 生成结果保存。
- 用户手动发布至 CreatiBI。

第一版不包含：

- 自动投放广告。
- 多人协作审批。
- 在线脚本富文本编辑器。
- 复杂素材关系树。
- 多 Agent 自主协商。
- 自动发布至 CreatiBI。

## 6. 用户流程

### 6.1 创建生成任务

1. 用户打开 ScriptAgent 工作台。
2. 用户上传参考视频。
3. 用户上传产品信息 Markdown。
4. 用户输入补充要求，可为空。
5. 用户选择行业：自动判断、游戏、电商。
6. 用户设置裂变脚本数量。
7. 用户点击生成。
8. 系统创建任务并进入异步执行。
9. 前端展示任务状态。

### 6.2 查看生成结果

1. 用户在历史记录中点击任务。
2. 系统展示任务详情。
3. 用户通过 Tabs 查看运行日志、视频分析、复刻脚本、裂变脚本、CreatiBI 写入状态。
4. 如果任务失败，展示失败原因。
5. 用户可以对非运行中的任务触发重试。

### 6.3 发布至 CreatiBI

1. 用户确认生成结果可用。
2. 用户点击发布至 CreatiBI。
3. 后端调用 CreatiBI Publisher。
4. 系统保存发布结果。
5. 前端展示脚本 ID、链接或失败提示。

## 7. 功能需求

### FR-001 前端工作台

系统必须提供简洁前端界面，首屏即为工作台，不做营销页。

验收标准：

- 页面包含上传区、输入区、生成按钮、历史记录、结果查看区。
- 页面视觉符合 CreatiBI Design System。
- 用户无需跳转多个页面即可完成创建任务。

### FR-002 参考视频上传

系统必须支持用户上传参考视频文件。

验收标准：

- 支持常见视频格式，至少包括 MP4。
- 上传后后端保存文件。
- 历史记录中保留原始文件名。
- 磁盘存储使用安全内部文件名。

### FR-003 产品 Markdown 上传

系统必须支持用户上传产品信息 Markdown 文件。

验收标准：

- 只允许 Markdown 类型文件。
- 后端保存 Markdown 内容。
- 模型生成时必须读取并使用该 Markdown。

### FR-004 补充要求输入

系统必须提供补充要求输入框。

验收标准：

- 用户可以输入脚本风格、禁用表达、目标平台、语言等要求。
- 该输入必须参与模型生成。
- 输入为空时任务仍可创建。

### FR-005 视频理解

系统必须调用 `qwen3.6-plus` 对参考视频进行理解。

验收标准：

- 输出行业判断。
- 输出命名统一表。
- 输出 Markdown 分镜表。
- 输出核心亮点总结。
- 分镜表必须符合用户提供的视频理解提示词约束。

### FR-006 复刻脚本生成

系统必须生成 1 条复刻脚本。

验收标准：

- 复刻脚本保留参考视频结构和节奏。
- 复刻脚本不直接复制原视频独有台词、品牌或版权元素。
- 脚本输出为 JSON。
- 脚本包含分镜数组。

### FR-007 裂变脚本生成

系统必须生成用户指定数量的裂变脚本。

验收标准：

- 裂变脚本数量等于用户设置值。
- 每条裂变脚本标注裂变方向。
- 每条裂变脚本说明保留元素和替换元素。
- 每条裂变脚本输出为 JSON。

### FR-008 脚本格式校验

系统必须在保存结果前校验脚本结构。

验收标准：

- 缺少标题、分镜数组、时间段、画面描述等关键字段时判定失败。
- 校验失败时任务状态为 `failed`。
- 校验失败原因必须保存并展示。

### FR-009 历史记录

系统必须保存每次任务。

验收标准：

- 历史记录展示任务标题、创建时间、状态、视频文件名、Markdown 文件名。
- 用户可以点击历史记录查看任务详情。
- 失败任务也必须保留。
- 程序关闭后重新启动，历史记录仍可查看。

### FR-011 本地持久化

系统必须将任务记录和上传文件持久化到本地。

验收标准：

- 任务记录保存到 SQLite。
- 上传视频和产品 Markdown 保存到本地文件目录。
- 重启后任务详情、生成结果和上传文件路径仍然可用。
- 删除 `data/` 或 `uploads/` 属于显式清理行为，不在普通重启范围内。

### FR-012 运行日志

系统必须展示任务执行过程摘要。

验收标准：

- 每个任务保存运行日志。
- 日志至少包含任务开始、视频理解、脚本生成、校验、完成或失败。
- 日志必须持久化，重启后仍可查看。
- 日志展示可审计步骤和错误摘要，不展示模型隐式逐字思维链。

### FR-013 任务重试

系统必须支持对每个非运行中的任务重新执行生成流程。

验收标准：

- 失败、完成、已发布任务都可以重试。
- 正在运行、分析、生成、发布中的任务不允许重复重试。
- 重试复用原视频、产品 Markdown、补充要求、行业和裂变数量。
- 重试会清空旧生成结果和发布结果，并重新生成。
- 重试会追加运行日志，保留任务历史可追踪。

### FR-010 CreatiBI 发布

系统必须支持用户手动发布生成脚本至 CreatiBI。

验收标准：

- 只有任务完成后才允许发布。
- 发布成功后保存 CreatiBI 返回结果。
- 发布失败后保留本地生成结果。
- 发布失败后允许重试。
- 发布必须真实调用 CreatiBI CLI/API 创建脚本，不允许仅把本地状态标记为已发布。
- 裂变脚本应作为复刻脚本的子任务创建；未获得有效来源任务 ID 时不得向 CreatiBI 传任意 `source-object`。
- 保存脚本内容时必须同时保留脚本名称和目标专案 ID，避免内容保存后 CreatiBI 任务显示为空名称或异常状态。
- 写入 CreatiBI 分镜脚本时必须按字段映射填充：`voiceover/subtitle` 写入 Copy，`visual/action/props_scene/shot_size` 写入 Description，`time_range/camera_intent/purpose/audio` 写入 Note，`action/props_scene/shot_size/audio` 同步写入分镜属性 `Movement/Prop/ShotSize/SoundEffec`。

### FR-011 裂变脚本生成

系统必须基于复刻脚本生成裂变脚本，而不是只基于视频分析一次性生成全部脚本。

验收标准：

- 复刻脚本生成完成并校验后，才进入裂变脚本生成。
- 裂变提示词必须包含复刻脚本 JSON。
- 裂变脚本必须继承复刻脚本的分镜数量、时间段、镜头功能和叙事顺序。
- 每条裂变脚本必须有明确裂变维度，并说明保留元素与替换元素。
- 裂变维度必须从三层分类中选择，并在 `metadata.fission_dimension` 中使用“层级-维度”格式。
- 视听层维度包括：换BGM、换音效、换色调/滤镜、换字幕&花字、换画幅、换配音(语速/声线)。
- 结构层维度包括：换开头钩子、换CTA、时长压缩/拉伸、变速·节奏调整、换首帧/封面、同素材高光重剪。
- 元素层维度包括：换局部角色/群演、换局部场景贴片、换局部道具/UI、字幕语言本地化。

### FR-012 通用对话

系统必须提供通用对话能力，用于讨论脚本策略、裂变方向、CreatiBI 发布问题、产品信息整理和一般创作问题。

验收标准：

- 前端必须提供独立“通用对话”入口。
- 用户可以创建新对话，也可以从历史对话中继续上下文。
- 对话消息必须持久化保存，关闭程序后再次打开仍可查看。
- 通用对话使用同一个模型配置，默认 `qwen3.6-plus`。

### FR-013 模型调用日志

系统必须记录每次模型调用的可见输入、输出和 token 用量。

验收标准：

- 脚本任务中的视频理解、复刻脚本生成、裂变脚本生成都必须记录模型调用。
- 通用对话每次回复都必须记录模型调用。
- 记录字段至少包含：调用场景、关联 ID、步骤、模型名、输入 JSON、输出文本、原始响应 JSON、输入 token、输出 token、总 token、耗时、错误信息、创建时间。
- 视频输入日志不得保存 base64 全量内容，必须用占位符替代。
- 前端必须提供“模型调用”入口，用于查看每次调用的输入、输出和 token 用量。

### FR-014 Agent 框架说明

当前 ScriptAgent 是单 Agent 顺序工作流，不是 ReAct（Reason + Act）框架。

验收标准：

- 前端可以说明当前对话/脚本 Agent 非 ReAct 工作流。
- 技术文档必须明确：前端使用 React；Agent 编排未使用 ReAct，如后续引入工具规划/行动循环，需要另行设计。

## 8. 视频理解需求

视频理解 Prompt 必须满足：

- 逐帧分析视频。
- 先判断行业类型：游戏或电商。
- 根据行业追加专属列。
- 至少包含产品卖点、画面描述、动作描述、视频信息、人物角色、道具场景、旁白对话、景别、镜头动机描述、叙事节奏描述、首帧画面描述、音效、BGM。
- 游戏类追加游戏素材类型、游戏 UI 描述。
- 电商类追加产品素材类型、产品展示描述。
- 只填视频中能直接观察到的内容。
- 无法判断填 `-`。
- 产品卖点可以推断。
- 画面描述必须详细逐帧分析。
- 同一道具、场景、角色必须全表统一称呼。
- 分镜表必须以 Markdown 表格输出。
- 最后必须输出核心亮点描述，为复刻脚本做准备。

## 9. 前端视觉需求

前端必须使用 CreatiBI Design System。

约束：

- 使用 `#8B4EEF` 作为主色。
- 使用 Inter + Noto Sans SC 字体。
- 输入框和按钮使用 6px 圆角。
- 卡片和面板使用 12px 圆角。
- 页面以白色和浅灰为主。
- 左侧历史记录区域使用紧凑列表。
- 结果区域使用 Tabs。
- 不使用 emoji。
- 不使用大面积渐变。
- 不使用装饰性 Hero。

## 10. 数据需求

系统至少保存：

- 任务 ID。
- 任务标题。
- 任务状态。
- 视频路径。
- 产品 Markdown 路径。
- 用户补充要求。
- 行业设置。
- 裂变数量。
- 视频分析 Markdown。
- 复刻脚本 JSON。
- 裂变脚本 JSON。
- CreatiBI 发布结果 JSON。
- 错误信息。
- 创建时间。
- 更新时间。

## 11. 状态需求

任务状态必须至少支持：

```text
pending
running
analyzing_video
extracting_structure
generating_replica
generating_fission
validating
completed
publishing
published
failed
```

## 12. 非功能需求

- 系统必须可本地启动和开发。
- API Key 不得暴露给前端。
- 上传文件必须限制类型和大小。
- 任务失败必须可追踪。
- 模型输出必须可保存、可复查。
- 任务运行过程必须可审计，但不得要求暴露模型隐式逐字思维链。
- 关闭并重新启动程序后，历史任务必须保留。
- CreatiBI 发布失败不能影响本地历史结果。
- 前端交互必须简洁，不增加无关说明文字。

## 13. Git 与文档维护约束

### 13.1 Git 使用约束

开发过程中，每次代码变更都必须使用 Git 管理。

具体要求：

- 修改前先查看工作区状态。
- 功能开发建议使用 `codex/` 前缀分支。
- 每一组相关变更完成后提交 Git commit。
- commit 信息应说明实际变更内容。
- 不混合提交无关改动。
- 不回滚用户或其他开发者已有改动。
- 如果存在未提交变更，继续开发前必须先确认这些变更是否属于当前任务。

### 13.2 需求文档维护约束

以下情况必须更新本文档：

- 新增或删除功能。
- 修改用户流程。
- 修改输入输出字段。
- 修改视频理解 Prompt 的核心约束。
- 修改 CreatiBI 发布方式。
- 修改历史记录字段。
- 修改前端页面结构。
- 修改验收标准。
- 修改第一版范围或非目标。

代码实现与本文档不一致时，应优先更新需求文档并说明变更原因。

## 14. 开发前待确认

- CreatiBI 创建脚本的最终字段标准。
- CreatiBI CLI/API 的实际调用方式。
- 视频临时 URL 或文件上传到 DashScope 的实现方式。
- `qwen3.6-plus` 当前账号地域的视频输入能力。
- Qwen 当前实现使用 Base64 data URL 传本地视频，默认限制 80MB。
- 第一版默认裂变数量。
- 第一版最大视频大小和最大视频时长。
- 是否需要多语言脚本。

## 15. 当前确认结论

第一版按以下方向开发：

```text
Go 后端
+ React 前端
+ CreatiBI Design System
+ SQLite 历史记录
+ qwen3.6-plus
+ 单 Agent 工作流
+ 用户手动发布至 CreatiBI
```

本文档将作为后续开发的需求基线，并在每次需求或实现发生变化时持续维护。
