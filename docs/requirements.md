# ScriptAgent 需求文档

> 最近维护：2026-08-28 · 当前实现基线：`main` · 产品地址见 [product-addresses.md](product-addresses.md)

## 0. 当前产品基线

当前 ScriptAgent 已从单一“上传视频生成裂变脚本”扩展为广告创作 Agent 工作台。当前主流程是：

1. 在产品资料中维护 Markdown、图片和视频资产。
2. 在创作空间中选择产品，定义广告目标、营销阶段、长期目标与限制。
3. 进入对话后由 Agent 按需读取资料、解析素材、选择 Skill，并输出策略、脚本或分镜提示词。
4. 需要确定性批处理时使用脚本 Workflow；需要探索和按需调用工具时使用 Agent Loop。
5. 在开发者模式或 Langfuse 中观察模型调用、步骤、Token、耗时与错误。

当前可用页面包括开始、历史、创作空间、产品资料、对话、设置和开发者模式。产品采用单页应用，统一入口为 `http://127.0.0.1:8080/`。

当前明确边界：

- 已支持多账号注册、登录和 Session 保护；退出后可以登录现有账号或继续注册新账号。
- 产品资料、创作空间、对话、任务、自定义 Skill、模型配置和观测数据按账号隔离；正式运营后台尚未上线。
- 图片生成、图片编辑和视频生成已提供能力配置，但只有接入对应执行任务后才视为完整产品能力。
- CreatiBI 发布依赖本机 CLI 和项目配置，不是默认必经流程。

## 1. 文档目的

本文档用于确认 ScriptAgent 第一版产品需求，并作为后续开发过程中的持续维护依据。

开发过程中，凡涉及功能范围、用户流程、接口、数据结构、模型行为、CreatiBI 写入方式、前端页面结构或验收标准的变更，都必须同步更新本文档。

## 2. 产品概述

ScriptAgent 是面向广告内容生产的 Agent 工作台。它以产品资料、视觉素材、创作空间目标和营销阶段为长期上下文，支持直接对话、素材复刻分析、脚本与分镜生成、裂变任务和可选的 CreatiBI 发布。

## 3. 目标用户

- 创意脚本策划人员。
- 广告素材生产人员。
- 需要基于参考视频快速生成复刻和裂变脚本的运营人员。
- 使用 CreatiBI 管理脚本和创意素材的内部团队。

## 4. 核心目标

- 降低参考视频拆解成本。
- 将视频分析结果稳定输出为详细 Markdown 分镜表。
- 基于产品 Markdown 生成可用的复刻脚本。
- 基于同一结构生成多条裂变脚本。
- 保存每次生成任务，方便回看和复用。
- 统一维护产品和产品 Markdown，创建任务时可复用已有产品。
- 部署给其他用户使用时，用户可以自行配置模型 Key、模型名和 Endpoint。
- 程序关闭后再次启动，历史任务和上传文件仍然保留。
- 在用户确认后将脚本写入 CreatiBI。

## 5. 第一版范围

第一版必须包含：

- 前端工作台页面。
- 参考视频上传。
- 产品 Markdown 上传。
- 产品资料库。
- 创建任务时选择已有产品。
- 用户补充要求输入。
- 裂变数量设置。
- 历史记录列表。
- 任务详情查看。
- 任务运行日志查看。
- 任务重试。
- 视频理解 Markdown 输出。
- 复刻脚本 JSON 输出。
- 裂变脚本 JSON 输出。
- 生成结果保存。
- 用户手动发布至 CreatiBI。

第一版不包含：

- 自动投放广告。
- 多人协作审批。
- 在线脚本富文本编辑器。
- 复杂素材关系树。
- 多 Agent 自主协商。
- 自动发布至 CreatiBI。

## 6. 用户流程

### 6.1 创建生成任务

1. 用户打开 ScriptAgent 工作台。
2. 用户先选择已有产品，或上传新的产品信息 Markdown 并保存为产品。
3. 用户上传参考视频。
4. 用户输入补充要求，可为空。
5. 用户选择行业：自动判断、游戏、电商。
6. 用户设置裂变脚本数量。
7. 用户为每条裂变脚本选择 1 个裂变方向。
8. 用户点击生成。
9. 系统创建任务并进入异步执行。
10. 前端展示任务状态。

### 6.2 查看生成结果

1. 用户在历史记录中点击任务。
2. 系统展示任务详情。
3. 用户通过 Tabs 查看运行日志、视频分析、复刻脚本、裂变脚本、CreatiBI 写入状态。
4. 如果任务失败，展示失败原因。
5. 用户可以对非运行中的任务触发重试。

### 6.3 发布至 CreatiBI

1. 用户确认生成结果可用。
2. 用户点击发布至 CreatiBI。
3. 后端调用 CreatiBI Publisher。
4. 系统保存发布结果。
5. 前端展示脚本 ID、链接或失败提示。

## 7. 功能需求

### FR-001 前端工作台

系统必须提供简洁前端界面，首屏即为工作台，不做营销页。

验收标准：

- 页面包含产品资产区、参考视频上传区、输入区、裂变方向区、生成按钮、历史记录、结果查看区。
- 默认首页必须是产品库，帮助短视频运营先看到可复用产品资产，而不是直接进入空白任务表单。
- 页面视觉符合 CreatiBI Design System。
- 用户无需跳转多个页面即可完成创建任务。
- 默认主导航面向广告内容运营用户，展示开始、历史、创作空间、产品资料和设置；开发者模式不得默认暴露。

### FR-002 参考视频上传

系统必须支持用户上传参考视频文件。

验收标准：

- 支持常见视频格式，至少包括 MP4。
- 上传后后端保存文件。
- 历史记录中保留原始文件名。
- 磁盘存储使用安全内部文件名。

### FR-003 产品 Markdown 上传

系统必须支持用户上传产品信息 Markdown 文件，并统一保存为产品资料。

验收标准：

- 只允许 Markdown 类型文件。
- 后端保存 Markdown 文件和产品记录。
- 产品记录必须在产品列表中可见。
- 模型生成时必须读取并使用该 Markdown。
- 创建任务时可以选择已有产品，也可以上传新 Markdown 并自动创建产品。

### FR-003A 产品资料库

系统必须提供产品列表，用于统一维护产品和产品 Markdown 文件。

验收标准：

- 用户可以新增产品并上传产品 Markdown。
- 产品列表展示产品名称、Markdown 文件名和更新时间。
- 产品库首页必须使用产品资产卡片展示产品封面/视觉占位、产品名称、已生成脚本数量、历史任务数量和最近生成时间。
- 产品资产卡片必须提供“生成新脚本”入口，并自动把对应产品带入创建任务流程。
- 用户选择产品后，可以在产品详情中预览该产品 Markdown 文件内容。
- Markdown 预览必须支持标题、段落和表格的可读化展示。
- 创建脚本任务时可以直接选择产品列表中的产品。
- 创建脚本任务时，产品资产必须作为第一步展示，提示用户产品 Markdown 会影响生成质量。
- 产品资料必须持久化，重启后仍然可用。

### FR-004 补充要求输入

系统必须提供补充要求输入框。

验收标准：

- 用户可以输入脚本风格、禁用表达、目标平台、语言等要求。
- 该输入必须参与模型生成。
- 输入为空时任务仍可创建。

### FR-005 视频理解

系统必须调用 `qwen3.6-plus` 对参考视频进行理解。

验收标准：

- 输出行业判断。
- 输出命名统一表。
- 输出 Markdown 分镜表。
- 输出核心亮点总结。
- 分镜表必须符合用户提供的视频理解提示词约束。

### FR-006 复刻脚本生成

系统必须生成 1 条复刻脚本。

验收标准：

- 复刻脚本保留参考视频结构和节奏。
- 复刻脚本不直接复制原视频独有台词、品牌或版权元素。
- 脚本输出为 JSON。
- 脚本包含分镜数组。

### FR-007 裂变脚本生成

系统必须生成用户指定数量的裂变脚本。

验收标准：

- 裂变脚本数量等于用户设置值。
- 创建任务前必须按裂变数量展示逐条裂变方向前置选项。
- 裂变方向必须以可点击卡片/按钮组展示，不应只使用后台式下拉框。
- 每条裂变脚本只能选择 1 个裂变元素；同一元素可以被多条裂变脚本重复选择。
- 用户选择的裂变方向必须按脚本顺序保存，第 N 个方向对应第 N 条裂变脚本。
- 如果用户选择了裂变方向，模型必须让第 N 条裂变脚本严格使用第 N 个方向。
- 每条裂变脚本标注裂变方向。
- 每条裂变脚本说明保留元素和替换元素。
- 每条裂变脚本输出为 JSON。

### FR-008 脚本格式校验

系统必须在保存结果前校验脚本结构。

验收标准：

- 缺少标题、分镜数组、时间段、画面描述等关键字段时判定失败。
- 校验失败时任务状态为 `failed`。
- 校验失败原因必须保存并展示。

### FR-009 历史记录

系统必须保存每次任务。

验收标准：

- 历史记录展示任务标题、创建时间、状态、视频文件名、Markdown 文件名。
- 用户可以点击历史记录查看任务详情。
- 失败任务也必须保留。
- 程序关闭后重新启动，历史记录仍可查看。

### FR-011 本地持久化

系统必须将任务记录和上传文件持久化到本地。

验收标准：

- 任务记录保存到 SQLite。
- 上传视频和产品 Markdown 保存到本地文件目录。
- 重启后任务详情、生成结果和上传文件路径仍然可用。
- 删除 `data/` 或 `uploads/` 属于显式清理行为，不在普通重启范围内。

### FR-012 运行日志

系统必须展示任务执行过程摘要。

验收标准：

- 每个任务保存运行日志。
- 日志至少包含任务开始、视频理解、脚本生成、校验、完成或失败。
- 日志必须持久化，重启后仍可查看。
- 日志展示可审计步骤和错误摘要，不展示模型隐式逐字思维链。

### FR-013 任务重试

系统必须支持对每个非运行中的任务重新执行生成流程。

验收标准：

- 失败、完成、已发布任务都可以重试。
- 正在运行、分析、生成、发布中的任务不允许重复重试。
- 重试复用原视频、产品 Markdown、补充要求、行业和裂变数量。
- 重试会清空旧生成结果和发布结果，并重新生成。
- 重试会追加运行日志，保留任务历史可追踪。

### FR-014 模型配置入口

系统必须提供模型配置入口，便于部署给其他用户后由用户自行配置模型。

验收标准：

- 前端提供配置页面，展示模型是否已配置。
- 用户可以保存 DashScope API Key、Endpoint 和模型名。
- 用户保存的模型配置优先于服务器环境变量。
- 后端不得在接口响应中返回完整 API Key，只能返回脱敏后的 Key。
- 未配置模型时，模型调用必须明确报错，不得静默失败。
- 配置页必须前置展示 API Key 安全提示，说明 Key 保存在当前部署的本地数据库，提醒不要公开分享数据库文件。
- 设置页必须提供开发者选项开关，用于显示或隐藏开发者模式。

### FR-010 CreatiBI 发布

系统必须支持用户手动发布生成脚本至 CreatiBI。

验收标准：

- 只有任务完成后才允许发布。
- 发布成功后保存 CreatiBI 返回结果。
- 发布失败后保留本地生成结果。
- 发布失败后允许重试。
- 发布必须真实调用 CreatiBI CLI/API 创建脚本，不允许仅把本地状态标记为已发布。
- 裂变脚本应作为复刻脚本的子任务创建；未获得有效来源任务 ID 时不得向 CreatiBI 传任意 `source-object`。
- 保存脚本内容时必须同时保留脚本名称和目标专案 ID，避免内容保存后 CreatiBI 任务显示为空名称或异常状态。
- 写入 CreatiBI 分镜脚本时必须按字段映射填充：`voiceover/subtitle` 写入 Copy，`visual/action/props_scene/shot_size` 写入 Description，`time_range/camera_intent/purpose/audio` 写入 Note，`action/props_scene/shot_size/audio` 同步写入分镜属性 `Movement/Prop/ShotSize/SoundEffec`。

### FR-011 裂变脚本生成

系统必须基于复刻脚本生成裂变脚本，而不是只基于视频分析一次性生成全部脚本。

验收标准：

- 复刻脚本生成完成并校验后，才进入裂变脚本生成。
- 裂变提示词必须包含复刻脚本 JSON。
- 裂变脚本必须继承复刻脚本的分镜数量、时间段、镜头功能和叙事顺序。
- 每条裂变脚本必须有明确裂变维度，并说明保留元素与替换元素。
- 每条裂变脚本只能基于 1 个裂变元素，不允许把多个裂变元素组合到同一条脚本中。
- 后端必须校验 `metadata.fission_dimension` 精准等于对应行选择的 1 个允许裂变维度；混合维度或顺序不匹配必须判为无效。
- 裂变维度必须从三层分类中选择，并在 `metadata.fission_dimension` 中使用“层级-维度”格式。
- 视听层维度包括：换BGM、换音效、换色调/滤镜、换字幕&花字、换画幅、换配音(语速/声线)。
- 结构层维度包括：换开头钩子、换CTA、时长压缩/拉伸、变速·节奏调整、换首帧/封面、同素材高光重剪。
- 元素层维度包括：换局部角色/群演、换局部场景贴片、换局部道具/UI、字幕语言本地化。

### FR-012 通用对话

系统必须提供通用对话能力，用于讨论脚本策略、裂变方向、CreatiBI 发布问题、产品信息整理和一般创作问题。

验收标准：

- 前端必须提供独立“通用对话”入口。
- 空对话首页必须提供任务式快捷入口，例如生成裂变方向、编写产品 Markdown、优化脚本，而不是长篇能力说明。
- 用户可以创建新对话，也可以从历史对话中继续上下文。
- 用户发送消息后，用户消息必须立即显示在对话区，不等待模型响应。
- 模型响应返回前，前端必须展示等待/思考状态。
- 模型响应返回后，助手消息必须以打字机效果逐步显示。
- 通用对话发送消息前可以选择产品库中的产品。
- 选择产品后，模型回复必须读取并引用该产品的 Markdown 内容。
- 当产品 Markdown 较长时，系统必须优先使用 embedding + Top-K 检索筛选相关章节，避免每轮无差别注入全文。
- embedding 不可用或检索失败时，系统必须回退到本地关键词章节筛选，避免通用对话不可用。
- 前端必须展示“本轮引用”的产品章节，包括章节标题、产品名、片段摘要和检索来源。
- 当对话消息超过阈值时，系统必须生成并保存长期会话摘要，用于后续对话上下文。
- 未选择产品时，通用对话按普通上下文对话执行。
- 如果用户问题要求产品信息，但产品 Markdown 中没有相关内容，模型必须明确说明无法从产品资料判断。
- 对话消息必须持久化保存，关闭程序后再次打开仍可查看。
- 通用对话使用同一个模型配置，默认 `qwen3.6-plus`。

### FR-013 模型调用日志

系统必须记录每次模型调用的可见输入、输出和 token 用量。

验收标准：

- 脚本任务中的视频理解、复刻脚本生成、裂变脚本生成都必须记录模型调用。
- 通用对话每次回复都必须记录模型调用。
- 记录字段至少包含：调用场景、关联 ID、步骤、模型名、输入 JSON、输出文本、原始响应 JSON、输入 token、输出 token、总 token、耗时、错误信息、创建时间。
- 视频输入日志不得保存 base64 全量内容，必须用占位符替代。
- 前端必须提供开发者模式，用于查看每次调用的输入、输出和 Token 用量。
- 开发者模式必须默认隐藏，只能在设置页的开发者选项开启后显示。
- 关闭开发者选项后，前端必须从开发者模式自动回到普通页面，避免普通运营用户误入。

### FR-014 Agent 框架说明

ScriptAgent 必须支持 ReAct（Reason + Act）式工具调用能力。第一阶段先应用于通用对话，脚本任务生成仍保留稳定顺序流水线。

验收标准：

- 通用对话必须通过 ReAct 编排器执行，可在回答前选择调用工具或内置 skill。
- ReAct 每轮模型动作必须在“调用工具”和“最终回答”之间二选一。
- 前端必须展示本轮 Agent 步骤，包括可见决策摘要、工具名、工具输入和工具观察。
- Agent 步骤不得要求或展示模型隐式逐字思维链，只展示面向用户可审计的决策摘要。
- 第一版开放工具必须以只读能力为主，包括产品列表、产品 Markdown 检索、产品 Markdown 摘要读取和内置 skill 调用。
- 内置 skill 必须作为本地工作流/提示词模板调用，不得执行外部命令。
- 内置 skill 必须至少包含：裂变策略、产品 Markdown 编写、脚本优化、素材多模态分析与视频复刻建议、Seedance 视频提示词生成。
- 前端通用对话必须展示可主动调用的内置 skill 列表，包括名称、分类和用途说明。
- 用户点击 skill 后，系统必须把对应调用指令写入对话输入框，由用户确认发送，不得误触发自动调用。
- 脚本任务生成是否迁移到 ReAct 编排，后续另行设计。

### FR-015 DataEye 爆款素材分析

系统必须支持基于 DataEye 爆款素材的创意方向分析。第一阶段以通用对话内置 skill 形式提供分析工作流；后续产品化为独立“爆款素材分析任务”。

验收标准：

- 通用对话可调用 `material_replication_analysis` 内置 skill，直接解析用户上传的图片或视频，返回设计方式、内容表达、视听结构、时间线与可执行的视频复刻建议；不得把没有投放数据的素材描述为爆款。
- 分析必须要求明确数据来源，包括 DataEye 产品 URL/ID/名称，或已导出的 `materials_raw.json`、`manifest_fast.json` 和视频文件。
- 分析不得编造曝光、播放、热度、点赞、评论、转发、下载、投放时间等指标。
- 如果只有素材视频而没有指标，只能总结创意内容特征，不得声称素材“高表现”。
- 产品化版本应提供：产品选择、DataEye 来源配置、近 30 天筛选、素材拉取任务、爆款分析报告、创意方向转裂变脚本入口。
- DataEye 拉取必须作为后端白名单任务执行，不能让普通用户通过 ReAct 对话执行任意系统命令。
- DataEye 登录态依赖用户本机或部署环境已有授权时，界面必须明确提示登录和数据权限要求。

### FR-015A 产品创意策略报告

产品库必须支持从单个产品触发创意策略报告，并允许把报告转入裂变脚本任务。

验收标准：

- 产品详情中必须提供“创意策略报告”区域。
- 用户可以在产品详情中配置 DataEye 来源，包括 DataEye URL、产品 ID、产品名、时间范围、媒体、国家/地区、排序指标、样本数、补充要求和素材备注。
- 第一版允许在真实 DataEye 拉取任务接入前，先基于产品 Markdown 与 DataEye 来源配置生成“策略预案”报告。
- 当没有真实素材指标时，报告必须明确标注数据状态为待拉取素材或待补充指标，不得编造爆款数据。
- 报告必须保存到本地 SQLite，关闭程序后再次打开产品仍可查看历史报告。
- 报告必须包含可直接用于脚本任务的“转裂变脚本任务摘要”。
- 产品详情必须提供“转裂变任务”入口，点击后进入脚本任务页，自动选中对应产品，并把报告摘要写入补充要求。
- 转裂变任务仍要求用户上传参考视频并确认裂变方向；系统不得在没有参考视频时静默创建脚本任务。

### FR-016 脚本转视频生成提示词

系统必须支持把已生成的复刻脚本和裂变脚本转成 Seedance 视频生成提示词。

验收标准：

- 任务结果页必须提供“视频提示词”Tab。
- 用户打开“视频提示词”Tab 后，后端读取当前任务的复刻脚本 JSON 和裂变脚本 JSON，即时生成提示词 Markdown。
- 提示词必须按脚本和分镜分组，不得把多条脚本混成一个提示词。
- 每个分镜提示词必须包含正向提示词、声音与字幕、负向提示词。
- 正向提示词应尽量包含时间段、画面描述、动作描述、景别、镜头动机、道具场景和视觉风格。
- 声音与字幕应包含旁白、字幕、音效、BGM；脚本缺失时必须说明无明确声音信息。
- 负向提示词必须限制文字乱码、Logo 变形、产品外观不一致、人物肢体畸形、镜头闪烁、低清晰度、无关品牌、水印、版权角色和夸大功效。
- 通用对话可调用 `seedance_video_prompt_writer` 内置 skill，获得同一套转换规则和输出结构。
- 第一版转换不额外调用模型，避免增加 token 成本；后续可增加模型润色开关。

### UI-001 界面质感与可读性

- 产品资产必须位于创建任务流程第一步。
- 产品库必须呈现为面向运营用户的资产首页，而不是左侧列表式后台页面。
- 裂变方向选择必须以逐条脚本编号和卡片按钮方式展示，便于用户确认每条裂变脚本的唯一裂变元素。

- 视频分析 Markdown 必须支持标题和表格的可读化展示。
- JSON 结果必须保留原始内容，同时优先展示脚本摘要信息。

## 16. 创作空间投放素材闭环升级

### 16.1 产品定位

创作空间从“长期目标、产品资料和执行记录容器”升级为面向小红书广告素材的生产与迭代工作台。系统围绕“发现有效素材、拆解创意基因、生成可控变量版本、记录投放结果、识别素材衰退、发起下一轮创作”形成闭环。

本次升级不改变 ScriptAgent 作为内部创作生产工具的定位，不自动投放广告，不自动调整预算或暂停计划。

### 16.2 首期用户场景

首期必须支持三种创作模式：

1. 复刻爆款：迁移参考素材的有效结构和节奏，不直接复制独有台词、人物、品牌、画面或版权元素。
2. 素材裂变：围绕母素材使用控制变量法生成多个实验版本。
3. 素材衍生：从评论、搜索词、用户问题、有效卖点和使用阶段中扩展新选题。

### 16.3 创作空间信息架构

创作空间详情必须包含：

- 项目概览：目标、产品、任务统计、素材状态、优胜素材和衰退预警。
- 素材库：统一管理参考素材、脚本、成片、笔记及其版本关系。
- 创作任务：创建和查看复刻、裂变、衍生任务。
- 实验与投放：维护实验组、版本变量和投放表现。
- 创意洞察：展示从素材及数据中提炼的机会和下一轮建议。
- 项目设置：维护平台、营销目标、基线、规则和数据来源。

现有空间目标、要求、产品关系和历史任务必须保留并兼容。

### FR-017 素材资产库

系统必须在创作空间内提供素材资产库。

验收标准：

- 素材支持参考视频、脚本、成片和笔记四类资产。
- 素材必须记录来源、平台、创作模式、生命周期状态和所属产品。
- 素材支持母子关系和版本关系。
- 素材支持卡片和列表视图，并可按类型、状态、创作模式和产品筛选。
- 历史脚本任务生成结果可以逐步迁移或映射为素材，不得因升级丢失。

### FR-018 爆款结构迁移

系统必须支持基于参考素材生成原创化复刻脚本。

验收标准：

- 输出原素材分析、爆款结构卡、产品映射、复刻脚本、差异说明和测试假设。
- 明确标注保留结构、替换元素和不可迁移元素。
- 不直接复制参考素材的独有台词、人物、商标、影视片段或其他受保护表达。
- 未提供真实投放指标时，只能分析内容特征，不得把素材描述为高表现或爆款。
- 生成前后均提供合规与版权风险提示。

### FR-019 投放导向素材裂变

现有裂变能力必须扩展为创意层和制作层两组维度。

创意层包括：钩子、人群、使用场景、核心卖点、证据形式、内容体裁。制作层沿用视听层、结构层和元素层维度。

验收标准：

- “严谨实验”模式下每个版本只能改变一个关键变量。
- “快速探索”模式允许每个版本改变二至三个变量，结果必须明确列出全部变化。
- 每个版本必须保存测试假设、保留元素和替换元素。
- 系统必须保留母素材与所有裂变版本的关系。
- 现有逐条裂变方向和顺序校验继续有效。

### FR-020 素材衍生

系统必须支持从母素材及用户洞察生成新的内容方向。

验收标准：

- 输入可包含评论、私信文本、搜索词、投放关键词、客服问题和人工洞察。
- 系统先生成衍生机会池，用户选择机会后再生成脚本。
- 每个机会包含用户问题、目标人群、搜索意图、内容角度、推荐体裁和验证目标。
- 衍生脚本必须记录与母素材的关系，但不得被标记为同一结构的裂变版本。

### FR-021 结构化脚本版本

系统必须提供轻量结构化脚本编辑和版本保存能力。

验收标准：

- 每个分镜可编辑时间段、画面、景别、动作、口播、字幕、音效、镜头目的和拍摄备注。
- AI 原始输出必须保留，用户编辑后保存为新版本，不直接覆盖。
- 每个版本记录创建来源、变化字段、创建时间和父版本。
- 脚本版本可以继续生成 Seedance 提示词或发布至 CreatiBI。

### FR-022 实验与投放数据

系统必须支持在不自动投放的前提下维护素材实验和表现数据。

验收标准：

- 第一阶段支持手工录入和 CSV/XLSX 导入。
- 素材可绑定外部广告创意 ID，但不得假设已连接聚光平台。
- 指标至少支持曝光、点击、互动、转化、消耗、CTR、CPC、CVR、转化成本和频次。
- 每次导入保存数据来源、统计窗口和导入时间。
- 诊断结果只能给出建议，不得自动暂停、调价或修改预算。

### FR-023 素材生命周期

素材状态统一为：`draft`、`analyzing`、`generating`、`reviewing`、`ready`、`testing`、`winning`、`stable`、`fatigued`、`archived`、`failed`。

验收标准：

- 生命周期判断默认使用创作空间或账户自身基线，不使用跨行业统一绝对阈值。
- 衰退判断至少参考 CTR 趋势、成本趋势、曝光与有效行为的边际变化和频次。
- 出价、预算、定向、价格、库存或落地页发生变化时，诊断必须提示归因干扰。
- 广告投放状态与内容资产状态分开保存；停止投放不等于删除或归档内容。

### FR-024 创意基因与洞察

系统必须为素材保存可比较的创意基因。

创意基因至少包含目标人群、用户痛点、使用场景、钩子、核心卖点、证据形式、内容体裁、情绪、CTA 和关键词。

验收标准：

- 创意基因可由模型建议，但必须允许用户修改。
- 实验诊断必须基于明确版本差异，不能仅根据素材名称推断。
- 洞察必须保存证据来源、建议、置信度和处理状态。
- 用户可将洞察一键转换为新的创作任务。

### 16.4 分期范围

阶段一：创作空间信息架构、素材库、三种创作入口、母子关系、结构化脚本版本。

阶段二：数据导入、实验管理、生命周期诊断和下一轮创作建议。

阶段三：聚光平台数据连接、搜索词和评论洞察、自动创建迭代任务。任何自动投放或预算操作需单独立项和确认。

## 17. 创意情报与外部数据产品化

### 17.1 产品闭环

系统新增一级模块“创意雷达”，将市场爆款、竞品账号、用户声音与自有投放表现统一转成可追溯的创意证据。闭环为：数据连接 → 同步与标准化 → 发现信号 → 用户确认 → 创意记忆 → 空间对话/创作任务 → 新版本 → 投放反馈。

### FR-025 数据连接中心

- 首版支持演示数据和 CSV/XLSX；真实连接通过统一 Adapter 扩展 DataEye、巨量引擎、巨量千川和小红书聚光。
- OAuth 平台必须由服务端生成授权地址、保存加密令牌并处理刷新/撤销；不得要求用户提交 Cookie 或账户密码。
- 每个连接展示能力范围、账户、状态、最近同步时间、数据标签和删除入口。
- 演示数据必须明确标记 synthetic，不得与真实表现混用。

### FR-026 创意信号与证据

- 信号至少包括市场机会、竞品策略变化、用户声音、优胜素材、疲劳预警和归因冲突。
- 每条信号保存来源、观察窗口、样本量、原始证据、置信度和更新时间。
- 热度数据不得描述为广告转化；观察性相关不得描述为因果结论。
- 用户可将信号转成复刻、裂变、衍生或单变量实验任务。

### FR-027 创意记忆

- 外部原始数据和自动信号不得直接进入长期 Prompt。
- 只有用户明确确认的信号才能成为空间级创意记忆。
- 记忆保存结论、证据引用、置信度、适用空间、最近验证时间和状态。
- 空间对话最多按相关性与时间读取少量活跃记忆；必须提示模型其为有时间边界的经验，与新证据冲突时优先展示冲突。
- `memory_events` 继续作为审计事件，不等同于长期创意记忆。

### 17.2 无广告账户 Demo 验收

- 用户可选择一个创意空间并载入内置演示数据源。
- 页面展示至少四类带证据和置信度的信号。
- 用户确认信号后，页面显示长期创意记忆，并在该空间后续对话上下文中可用。
- 用户可从信号预填“下一轮可验证素材实验”的对话任务。
- 删除演示连接或撤销真实授权的能力在正式多租户发布前补齐。

### FR-028 竞品监控

- 用户可在创意雷达添加竞品名称、平台、账号/广告库链接与监控关键词，并绑定创意空间。
- 无真实数据连接时只允许运行明确标记为 synthetic 的演示扫描。
- 数据源按可信度分级：官方广告库/API、授权第三方素材情报、公开网页搜索、用户文件导入；页面必须展示来源等级。
- Web Search 只用于发现公开页面、账号更新与内容线索，不得把搜索排名或页面摘要解释为投放效果。
- 扫描结果统一生成 `competitor_change` 等创意信号，保存来源、时间窗口、样本量和证据；用户确认后才进入长期记忆。
- 第一阶段使用手动扫描；定时监控、失败重试、去重和变化检测在连接真实数据源后启用。
